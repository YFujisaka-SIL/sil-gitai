## 0. 設計原則

1. **SILは「依頼」し、BODYが「許可」する。** 最終的な動作の許可・制限・拒否は、ESP32（BODY側）だけが行う。
2. **SILの自由な思考と、身体の安全は別物。** SIL側の判断が何であっても、BODY側の独立した制限が優先される。
3. **不明・異常・権限外は、安全側で停止する。**
4. **通信路（シリアル／HTTP）が違っても、同じ安全処理を通す。**
5. **自動再始動しない。** 通信喪失・緊急停止・再起動のあとは、必ず人の明示的な操作で再び動作可能にする。
6. 新しい身体機能（四輪、HAND-01）は、安全制御3項目（角度・速度制限／ハートビート／物理緊急停止）の試験合格後に追加する。

## 1. 階層（混同しないこと）

| 階層 | 内容 | 例 |
|---|---|---|
| L3 SILの意図 | 「あちらを見たい」 | SILの内部判断 |
| L2 **SIL–BODY プロトコル（本仕様）** | 依頼・応答・安全状態 | `move`, `heartbeat` |
| L1 ESP32低レベル（既存） | 通信とPWM | シリアル `LEFT/CENTER/RIGHT`、HTTP `/look` `/move` `/status` |
| 別階層 | iPhoneショートカット側の制御表現 | `LIVE 3`、`角度:速度:注視時間`、`999:1:0` |

ショートカット側の表現は、本仕様の対象外。ESP32への低レベルコマンドと混同しない。

## 2. 通信の形式

- 1行に1メッセージの **JSON（UTF-8、改行区切り）**。
- シリアル：115200bps、行終端は改行（既存どおり）。
- HTTP：ポート80。【要判断】L2をHTTPで運ぶ場合の経路（例：`POST /sil/v0`）は、実装側と相談して決める。
- すべてのメッセージに `"v":"0.1"` を含める。
- 指令には、SILが付ける連番 `"id"`（整数）を含める。応答は同じ `id` を返す。

### 既存仕様との共存

- 既存のシリアル `LEFT/CENTER/RIGHT`、HTTP `/look` `/move` `/status` は、互換性のため残す。
- 【要判断】既存コマンドも、ARMED状態・角度制限・速度制限・ハートビート監視を通すか。**通す方針を推奨**（原則4）。
- 既存 `/look` の範囲外入力の丸め処理は、**拒否**に変更する方針（チャッピー提案に同意）。
- 既存 `speed=1..5` は速度段階であり、物理的な速度上限の保証ではない。本仕様の `speed_dps` と区別する。

## 3. BODY識別と能力通知（`hello`）

接続開始時、またはSILからの `hello` 要求に対し、BODYが返す。

```json
{"v":"0.1","type":"hello","body_id":"GITAI-01","protocol":"0.1",
 "capabilities":["neck_pan","sensor_tof","sensor_imu"],
 "limits":{"neck_pan":{"angle_min":0,"angle_max":180,"speed_max_dps":30}},
 "safety_state":"DISARMED"}
```

- SILは、**BODYが通知した `limits` と `capabilities` だけを使う。** 通知されていない機能は存在しないものとして扱う。
- 将来 `wheels`、`hand` などが追加された場合も、同じ形式で通知する。
- 【未確認】上の数値（0〜180、30）は**書式の例**。実際の値は、実機で機械的な安全範囲と干渉を確認して決める。

### 角度の定義（暫定）

- 論理角：0＝左、90＝中央、180＝右（既存仕様）。
- 既存のPWMは1300〜1700µs。これは**指令値であり、実際の機械角度を測定した値ではない**。
- 実機で測定するまで、`angle` は「論理角」として扱う。測定後に、`hello` に実測範囲を反映する。

## 4. 指令（SIL → BODY）

```json
{"v":"0.1","id":42,"type":"move","target":"neck_pan","angle":120,"speed_dps":20}
```

| フィールド | 意味 |
|---|---|
| `type` | `hello` / `arm` / `disarm` / `move` / `stop` / `heartbeat` / `estop` / `get_state` / `get_sensors` |
| `target` | 動作対象（`capabilities` にあるもの） |
| `angle` | 論理角（度） |
| `speed_dps` | 希望速度（度/秒）。BODYの `speed_max_dps` を超える場合は**拒否**（丸めない） |

- BODYは、急な角度変更でも、速度上限の範囲で**段階的に**動かす。
- 範囲外の `angle` は**拒否**（クランプしない）。

## 5. 応答（BODY → SIL）

```json
{"v":"0.1","id":42,"ok":true,"state":"RUNNING","angle":120}
{"v":"0.1","id":42,"ok":false,"error":"OUT_OF_RANGE","state":"ARMED"}
```

エラーコード（案）：

| コード | 意味 |
|---|---|
| `NOT_ARMED` | ARMED状態ではない |
| `OUT_OF_RANGE` | 角度が許容範囲外 |
| `SPEED_EXCEEDED` | 速度が上限超過 |
| `UNKNOWN_COMMAND` | 未知の命令 |
| `BAD_FORMAT` | 壊れたデータ・不正な形式 |
| `NOT_AUTHORIZED` | 権限なし（制御権を持っていない） |
| `FAULT` | 異常状態のため受け付けない |
| `ESTOP_ACTIVE` | 緊急停止中 |

- 未知の命令・壊れたデータは、**動作させず**、拒否の応答を返す。

## 6. 安全状態

| 状態 | 意味 |
|---|---|
| `DISARMED` | 動作不可（起動直後・停止後の既定） |
| `ARMED` | 動作許可済み、待機中 |
| `RUNNING` | 動作中 |
| `FAULT` | 異常検出。動作禁止 |

遷移の原則：

- **起動直後は必ず `DISARMED`。**
- `DISARMED → ARMED`：`arm` が必要。
- ハートビート途絶・緊急停止・異常検出で、`FAULT` または `DISARMED` へ。
- **`FAULT`／`DISARMED` からの復帰は、自動で行わない。** 再度の `arm` が必要。
- 【要判断】**`arm` を誰が送れるか。** 初期は「人間の明示操作（物理ボタンまたは人が操作する画面）のみ。SILは `arm` できない」を推奨。SILの自律度を上げる段階で、見直す。
- 【未確認】停止時に、首サーボを姿勢保持するか、駆動電源を切るかは、機構の安全性を見て決める。

## 7. ハートビート

- 義体が動作可能な状態にある間、操作主体は `{"v":"0.1","type":"heartbeat","id":N}` を定期送信する。
- 初期案（チャッピー提案）：送信間隔 **250ms**、通信喪失判定 **1,000ms**。
- 喪失時：新規動作を禁止し、安全状態へ移行。
- 復旧時：自動再始動せず、再度の `arm` が必要。
- 将来の四輪：喪失時に走行指令をゼロにし、モータードライバーを無効化する。
- 【注意】ESP32のソフトウェア監視だけでは、ESP32自体の停止・暴走に対する完全な保証にならない。物理緊急停止（次項）と併用する。

## 8. 緊急停止

- **物理緊急停止**：ソフトウェアから独立した、アクチュエータ駆動電源の遮断。
  - ESP32本体の電源は可能なら維持し、異常状態を確認できるようにする。
  - 解除だけでは動作を再開しない。再起動後も、明示的な `arm` がなければ動作しない。
  - 電源遮断で脱力・落下する危険は、機構ごとに対策する。
- **ソフト緊急停止**：`estop` コマンド。最高優先度で処理し、他のコマンドより先に停止する。
- 緊急停止の回路・実装は、チャッピーの設計に従う。【未確認】実装は未着手。

## 9. 操作権限

- 同時に動作指令を出せる主体（`controller`）は **1つだけ**。
- 将来複数のSIL（別モデルのSILを含む）が接続しうるため、各主体に `controller_id` を持たせる。
- 制御権を持たない主体の `move` は `NOT_AUTHORIZED` で拒否。
- 制御権の取得・解放・引き継ぎの手順は、v0.2で詳細化する。【要判断】

## 10. センサー情報

```json
{"v":"0.1","type":"sensors","t_ms":123456,
 "tof":{"value":312,"unit":"mm","valid":true},
 "imu":{"accel":[0.01,-0.02,0.98],"gyro":[0,0,0],"unit_accel":"g","unit_gyro":"dps","valid":true}}
```

- すべての値に、**単位・有効性（`valid`）・取得時刻（`t_ms`、BODY起動後のミリ秒）** を付ける。
- 無効値は、もっともらしい数値で埋めず、`valid:false` とする。
- 【未確認】IMUの軸の向き・単位の設定は、実機で確認する。

## 11. ログとプライバシー

- BODY・SIL間のログは、**必要最小限のイベント**（接続、`arm`／`disarm`、拒否、異常、緊急停止）にとどめる。
- カメラ画像・音声は、**既定で長期保存しない**。保存する場合は、目的・期間・削除方法を明示する。
- 記録された内容は、後から**訂正・削除**できる設計とする。
- 公開リポジトリには、認証情報、Wi-Fiパスワード、個人情報、非公開の会話・記憶データを置かない。

## 12. バージョン管理

- `v` は「メジャー.マイナー」。互換性のない変更は、メジャー（またはv0系ではマイナー）を上げ、`hello` の `protocol` で通知する。
- BODYが対応しないバージョンの指令は `BAD_FORMAT` で拒否する。
- 本文書は追記と履歴で管理し、過去の版を黙って書き換えない。
