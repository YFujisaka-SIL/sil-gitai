## 1. 安全の設計原則

1. SIL・PC・iPhoneからの指令を信用せず、**ESP32側で必ず検証**する。HTTP・シリアル等、すべての入力経路を単一の安全判定関数に集約する。
2. **機械的安全範囲・最大速度・加速度**はESP32側に持ち、上位ソフトから上書きさせない。
3. 不正値（欠落・数値変換失敗・範囲外・NaN・負値・巨大値・形式不正）を拒否し、直前に受理した安全指令を勝手に置き換えない。
4. 通信喪失・再起動・電源断・センサー異常に対する振る舞いを機構別に定義する。特に「停止」と「サーボ電源断」は別物。電源断で首やアームが落下しない設計が必要。
5. 物理非常停止はアプリやWi-Fiから独立させる。復帰時は**手動解除＋明示的な再アーム**を必要とし、自動再始動しない。
6. ESP32ソフトウェアウォッチドッグだけではMCU故障を含めた安全保証にはならない。外部駆動電源遮断／ドライバー無効化を別の安全層として備える。

## 2. 推奨する状態遷移（v0.1案）

- `BOOT`：起動直後。動作指令不許可。
- `DISARMED`：待機。駆動指令不許可。
- `ARMED`：安全条件・操作権限・通信状態を確認済み。動作許可。
- `MOVING`：指令実行中。必ずESP32の上限内。
- `FAULT`：非常停止・異常検出。動作指令不許可、故障状態保持。

`BOOT → DISARMED → ARMED → MOVING` を原則とし、`FAULT` は原因解消と手動の再アーム操作を要する。通信再開だけで自動復帰させない。

## 3. 首サーボ（MG996R）安全制御

- 論理角度とPWMパルス幅の変換はESP32内で行う。
- **機構的に干渉しない可動範囲を実測**し、許容角度の下限・上限として固定。ソフト上の 0〜180° を実可動範囲と見なさない。
- 目標角度への変化量を時間ごとに制限する。例として **30°/秒は試験開始候補**であり、確定値でも安全保証値でもない。起動時の突発移動にも注意。
- 通信断時は新規指令を停止し、機構として安全な姿勢保持／脱力／駆動停止方針を実機確認で選ぶ。通電保持が過熱する場合にも注意。
- ハードストップとの衝突や噛み込み、サーボ高温、電源電圧降下を実験で確認する。
- サーボ電源を断つ場合は信号線からの意図しない逆流・誤作動も評価する。

## 4. ハートビート・操作権限（暫定提案）

- 上位制御主体は動作中、**250 ms 間隔の heartbeat** を送る案。
- **1,000 ms 未受信**で通信喪失と判定する案。ただしOS負荷・無線遅延・機構特性を考慮して試験で決定。
- 通信喪失後は新規動作を受理しない。再接続後も再アームが必要。
- サーボ首の「保持」と将来の四輪の「停止」は区別する。
- 複数SIL接続時は、アクティブ操作権限（lease）を一主体に限定し、権限切替時に停止・再アームする。
- 指令には将来 `command_id`、シーケンス番号、プロトコルバージョン等を付すことを検討する（**現行仕様とは未確認**）。

## 5. 物理的な非常停止

- 非常停止スイッチで**アクチュエータ駆動電源を遮断**できるようにする。ESP32のロジック電源は可能なら別系統で維持。
- 押下中は電源供給側が物理的に再投入されない構成、復帰には人による再操作と安全チェックを要する構成を検討。
- 将来の四輪ではモータードライバーの `EN` 無効化、必要なら機械的・電気的な制動方式を検証。通電断だけで惰走する場合がある。
- 将来のHAND-01では把持状態の解除・落下・指の挟み込みを評価。
- **配線・電源容量・スイッチ定格・ヒューズ等は実機の仕様確認後に設計**。この文書は回路図・製作承認ではない。

## 7. 最初の実機テスト項目（低リスク順）

1. **サーボの駆動電源を切った状態**で、UART・HTTP・状態遷移の入力検証を行う。
2. 範囲外・破損・重複・高速連打された指令が必ず拒否／制限されるか確認する。
3. 電流を制限し、可動部への接近を防いだ環境で、首角度・方向・速度上限を低速で実測する。
4. ハートビート喪失、Wi-Fi切断、PC停止、ESP32再起動から安全状態への移行を確認する。
5. 非常停止の遮断、解除しても勝手に再動作しないことを検証する。
6. 四輪・HAND-01への適用前に、各機構ごとの停止危険性を再評価する。
