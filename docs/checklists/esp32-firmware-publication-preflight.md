# 現行ESP32ファームウェアをGitHub公開する前の確認手順

- 作成：チャッピー、2026-11-05
- 状態：**準備用チェックリスト。まだソース本体は未受領・未点検**
- 適用先：GITAI-01／ESP32 の `.ino`、`.cpp`、`.h`、Pythonの旧クライアント、依存設定等
- 目的：**実機で動いているコードを壊さず、秘密情報を公開せずに共同レビュー可能にする**

## 現時点の確認結果（GitHub側だけ）

- GitHubの `main` と設計ブランチを確認したが、**現行ESP32コードはまだ見つからない**。
- したがって、**Wi-Fiパスワードがソースに存在するか、既に除去されたかの判定はまだできない**。
- 本チェックリストの登録は、ファームウェアの安全性・秘密情報の検査完了を意味しない。

## 1. VAIO側に原本を残す（公開前）

- [ ] 動作中のESP32のスケッチ一式をVAIO内にコピーしてバックアップする。ライブラリ・ボード設定・実際のGPIOも記録。
- [ ] そのコピーから **GitHub公開用の別フォルダ**を作る。原本は変更しない。
- [ ] スケッチ内にある他ファイルへの参照、フォルダ、Pythonクライアントも洗い出す。
- [ ] 公開するのは、秘密を除去した確認済みコピーだけにする。

## 2. パスワード等を人間がローカル確認する

以下の文字列を **VAIO内のエディタで検索**。検索結果はパスワードを含む可能性があるため、**そのままチャットやGitHubへ貼らない**。

| 対象 | 検索・点検の例 |
|---|---|
| 通常Wi-Fi | `WiFi.begin(`、`ssid`、`password`、`passwd` |
| ESP32アクセスポイント | `WiFi.softAP(`、APパスフレーズ、固定SSIDの周辺コード |
| API / 操作認証 | `API_KEY`、`token`、`secret`、`Authorization`、`Bearer` |
| リモート更新・外部サービス | OTAパスワード、MQTT / HTTP認証、クラウドキー |
| 人に関する情報 | 実名、メール、電話、住所、個人の会話、ログ、画像 |
| ローカル情報 | Windowsの絶対パス、ユーザー名、私有IP、公開不要な構成情報 |
| 鍵・証明書 | 秘密鍵、`.pem`、`.key`、`.p12` |

**SSID自体は通常パスワードではない**が、自宅のSSIDや私有ネットワーク情報は不用意に公開しない。デバイス標準名 `GITAI-01` は公開用資料に使えるか別途判断。

## 3. ソースから秘密情報を分離

- [ ] Wi-Fiや認証の実値を、Gitに入れないローカルファイル（例：`firmware/secrets.h`）に移す。
- [ ] GitHubには `firmware/secrets.example.h` のような**ダミー値だけ**のテンプレートを置く。
- [ ] 構築時に `secrets.h` を読み込むようコードを変更する場合は、変更前の動作を比較する（特にAP起動・HTTP応答・PWM起動時）。
- [ ] 秘密情報を含むファイルが追跡対象になっていないことを確認する。
- [ ] 公開用に直したプログラムの動作試験が済むまで、実機のファームを書き換えない。

例（**本物の秘密は入力しない**）：

```cpp
// secrets.example.h — 例。実機用 secrets.h は Git 管理しない。
#pragma once
#define GITAI_WIFI_SSID "SET_LOCAL_SSID"
#define GITAI_WIFI_PASSWORD "SET_LOCAL_PASSWORD"
#define GITAI_AP_PASSWORD "SET_LOCAL_AP_PASSWORD"
```

**実装注意：** ソースが現在APを無認証で動かす設定か、既に認証を使っているかは不明。秘密分離に伴って無断でWi-Fiの認証方式を変更しない。アクセス保護は別途設計・試験。

## 4. Gitで登録前に確認（公開用コピー）

以下は**ローカルで実行する確認例**。コマンドの出力に秘密情報が含まれる場合があるため、結果を外部に貼らない。

```bash
git status --short
git check-ignore -v firmware/secrets.h
git diff --cached --name-only
git diff --cached
```

- [ ] `git check-ignore` で実ファイルが除外対象になることを確認（ただし**既にGit追跡中なら .gitignore だけでは除外できない**）。
- [ ] `git diff --cached` でGitに登録される変更の**実際の中身**を目視点検。
- [ ] 過去のコミット履歴に実際の鍵を入れたことがある場合、履歴からも見えてしまうため鍵・パスワードを**失効・変更**し、履歴修正の要否を検討。
- [ ] 自動検出ツールの結果だけを信頼せず、コメント・サンプル・設定ファイルを再確認。

## 5. 公開の最小単位

まず現行コードの**スナップショット（動作を改変していないものの秘密除去版）**を、mainではない作業ブランチに登録する。その後に共同レビューする。

含めたい情報：

- [ ] `firmware/` 内にESP32ソースと依存関係・ボード種別・ビルド手順
- [ ] `docs/hardware/` に配線表（GPIO、サーボPWM、I2C、電源系統、共通GND、センサー）
- [ ] `docs/protocol/` に現行のHTTP/シリアルAPIと応答例（実機一致を確認したものだけ）
- [ ] 必要な場合だけ、秘密を除去した旧Pythonクライアント（`neck.py`、`server.py`など）
- [ ] 実機検証状況（起動／シリアル／AP接続／センサー／サーボ）を明記

## 6. 公開後の改修順

1. **現行コードを読むだけのレビュー**：旧API、サーボ挙動、起動時指令、例外時の挙動を洗い出す。
2. ARMボタンとE-stopの最終ピン決定。GPIO競合、ブートストラップ、電流・電圧を確認。
3. ハード駆動OFFでパーサー・安全状態・heartbeat・旧APIゲートのテスト。
4. 駆動許可の物理遮断回路、モーターの低速・過負荷・異常時試験を行う。
5. v0.1接続仕様との整合試験。**未確認の状態で安全機能実装済みとは表記しない**。

## 7. 現時点の判定

**公開準備は文書と除外ルールまで。実際のWi-Fiパスワード検査・機密情報の除去・コードの安全確認は未実施。現行のESP32スケッチをVAIO側で確認する必要がある。**
